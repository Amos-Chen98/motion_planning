# pcd_self_filter

A standalone ROS 1 node that removes robot body returns from `sensor_msgs/PointCloud2` messages using the robot's configuration at the cloud timestamp. It reuses [robot_body_filter](https://github.com/ctu-vras/robot_body_filter) for geometry processing, containment tests, and coordinate transforms. Filtering serves the obstacle-avoidance pipeline; FAST-LIO continues to receive its original LiDAR input.

```text
cloud_registered_body → pcd_self_filter_node → cloud_self_filtered → voxel_mapping → motion_primitive_planner
```

## Dependencies and Build

The wrapper requires C++17, `robot_body_filter` 1.3.2, `tf2_sensor_msgs`, PCL, TinyXML2, and the ROS packages declared in `package.xml`. Install binary dependencies with `rosdep` after sourcing the built `jsk_aerial_robot_ws` underlay:

```bash
cd /path/to/motion_planning_ws
source ../jsk_aerial_robot_ws/devel/setup.bash
rosdep install --from-paths src --ignore-src -r -y
catkin build pcd_self_filter
source devel/setup.bash
```

For manual installation, the packages are `ros-noetic-robot-body-filter` and `ros-noetic-tf2-sensor-msgs` on Noetic, or `ros-one-robot-body-filter` and `ros-one-tf2-sensor-msgs` on ROS-O (`ROS_DISTRO=debian`). The node creates the upstream filter through its `pluginlib` factory to support binary builds.

### Source Fallback

If binary packages are unavailable, add the missing dependencies to an initialized workspace with `wstool`. Run from `motion_planning_ws`, adding only packages not already provided by the workspace or underlay:

```bash
wstool set -t src robot_body_filter --git https://github.com/ctu-vras/robot_body_filter.git -v 1.3.2
wstool set -t src tf2_sensor_msgs --git https://github.com/ros-gbp/geometry2-release.git -v release/noetic/tf2_sensor_msgs/0.7.7-1
wstool update -t src robot_body_filter tf2_sensor_msgs
rosdep install --from-paths src --ignore-src -r -y
catkin build pcd_self_filter
source devel/setup.bash
```

When switching back to binary packages, remove the corresponding `wstool` entries, move the source checkouts out of `src`, and clean and rebuild the affected packages.

## Launch and Interfaces

Start the robot description and state publishers before launching the filter. The configured robot description parameter, TF for all filtering links, and TF between the cloud frame and the world frame must be available. Joint transforms must reflect measured robot state rather than candidate configurations generated by a planner.

The default configuration uses the `dragon` namespace and `world` frame. Adjust the launch arguments for other robots or topic layouts.

```bash
roslaunch pcd_self_filter pcd_self_filter.launch
```

To feed the filtered output into the accompanying mapper, start it in a separate terminal with the workspace sourced:

```bash
roslaunch voxel_mapping voxel_mapping.launch pcl_topic:=/dragon/cloud_self_filtered
```

The accompanying planner launch enables the filter by default. Build the integration packages before using it, and let the planner launch start the filter and mapper instances:

```bash
catkin build voxel_mapping motion_primitive_planner
roslaunch motion_primitive_planner whole_body_motion_primitive_planner.launch
```

To restore the direct, unfiltered connection to the mapper:

```bash
roslaunch motion_primitive_planner whole_body_motion_primitive_planner.launch enable_self_filter:=false
```

| Interface or Parameter | Default and Description |
| --- | --- |
| `~input` | `/dragon/cloud_registered_body`; `sensor_msgs/PointCloud2`, remappable |
| `~output` | `/dragon/cloud_self_filtered`; `sensor_msgs/PointCloud2`, remappable |
| `~diagnostics` | Diagnostic array containing input and retained point counts, filtered ratio, processing time, success and failure counts, and last timestamps |
| `robot_ns` | `dragon` |
| `robot_description_param` | `/dragon/robot_description` |
| `tf_prefix` | Defaults to `robot_ns`; an empty prefix is supported |
| `world_frame_id` | `world`; frame used for filtering and output |
| `padding` | `0.02 m`; independent of the planner's obstacle inflation radius |
| `per_link_padding` | Upstream per-part padding dictionary, empty by default; names include the TF prefix, such as `dragon/battery1` |
| `tf_timeout` | `0.2 s`; a shared wall-clock deadline for all required transforms at the cloud timestamp |
| `queue_size` | 5 input clouds |
| `debug` | `false`; enables upstream geometry and removed-point visualization |

Use the `input_topic` and `output_topic` launch arguments to remap the input and output. Load custom parameters with `config:=/path/to/config.yaml`. The planner launch exposes `pcl_topic` for the input before filtering, along with `filtered_pcl_topic`, `self_filter_config`, `self_filter_debug`, and `enable_self_filter`. Input and output topics must differ to avoid a feedback loop.

The output preserves the input sampling timestamp and additional fields such as `intensity`, while expressing XYZ in the configured world frame. Supported clouds use native byte order and scalar `FLOAT32` XYZ fields. Organized clouds, including those with row padding, are compacted into unorganized clouds, and points with NaN or infinite XYZ coordinates are removed.

Invalid message layouts, zero timestamps, an unavailable model, or missing transforms at the cloud timestamp cause the entire frame to be dropped with a diagnostic report. The node never falls back to the latest TF or to unfiltered input. Valid empty clouds and results in which all points were removed are published normally; filtering failures do not produce empty output clouds.

## Filtering Model and Debugging

The node creates a private URDF copy at `~filter_robot_description` and uses only collision geometry already defined in the URDF. All collision elements are preserved, including their origins and mesh scales. Links without collision geometry are excluded from filtering, even if they have visual geometry; no collision elements are generated from visuals. Such links remain in the URDF tree but are not added to the required body TF frames. Link names and joint parent/child references are normalized to use the configured TF prefix. The original `robot_description`, robot dynamics model, and TF publishers remain unchanged. The model must contain at least one collision element for the filter to initialize.

Only containment tests are enabled by default; distance clipping and shadow tests are disabled. The upstream implementation represents non-convex collision meshes as convex hulls, which may also remove environment points in a part's concavities or internal gaps. Coarse collision geometry may cover space beyond the physical part. Parts without collision geometry contribute no filtering volume. Start with small padding and calibrate it using recorded clouds near real obstacles. The planner's `DilateRadius` is not a suitable substitute for self-filter padding.

Enable visualization for a standalone instance with:

```bash
roslaunch pcd_self_filter pcd_self_filter.launch debug:=true
```

In RViz, set Fixed Frame to the configured world frame and add the following topics for the default namespace and node name:

- `/dragon/pcd_self_filter/robot_model_for_contains_test`: `MarkerArray` showing filtering geometry.
- `/dragon/pcd_self_filter/scan_point_cloud_inside`: points removed by containment tests.
- `/dragon/cloud_self_filtered`: filtered output cloud.

The planner launch uses the node name `whole_body_motion_primitive_planner_self_filter`; its debug topics are under that node's private namespace. Use `self_filter_debug:=true` to enable them through the planner launch. Monitor the corresponding `diagnostics` topic to detect output interruptions caused by missing TF.

If model initialization fails, correcting the robot description parameter triggers another attempt. Restart the node after changing configuration files or geometry resources. The active filtering model is a startup snapshot. To include a new payload in filtering, define its collision geometry in the URDF and restart both the filter and mapper.

## Map Rebuilding and Rosbag Playback

Restart `voxel_mapping` when first enabling the filter to clear accumulated robot body returns. Changing the input topic alone does not remove existing occupied voxels. This package neither permanently clears historical voxels inside the current body envelope nor treats occluded regions as free space. Run only one mapper publishing to a given occupancy map topic.

For playback, record the input cloud topic, `/tf`, and `/tf_static`, and save the corresponding original `robot_description`. Enable simulated time, load the model, and start the filter and mapper before playing the bag. If the bag contains TF, avoid running another state publisher for the same frames.

```bash
rosparam set /use_sim_time true
# Load the robot description and launch the filter and mapper before playback.
rosbag play --clock recording.bag
```

Filtering uses one configuration per cloud timestamp and does not apply per-point motion compensation. Rapid articulation during a scan may therefore leave residual body returns; use recorded data to determine suitable operating conditions. Filtering failures stop new map updates. The `last_success_stamp` diagnostic supports upstream freshness monitoring; this package does not change the planner's handling of stale maps.
