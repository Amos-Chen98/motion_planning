# sync_data

`sync_data.sh` is the manual bidirectional sync entrypoint for:

- local `multilink_copilot/data`
- your private Google Drive destination configured outside git

## Setup

Move into the script directory first:

```bash
roscd multilink_copilot/bin
```

Prepare the local-only config file:

```bash
cp sync_data.local.env.example sync_data.local.env
```

Then edit `sync_data.local.env` and fill in:

- `MULTILINK_COPILOT_SYNC_REMOTE_DATA_DIR`
- `MULTILINK_COPILOT_SYNC_REMOTE_BACKUP_DIR`

Requirements:

- `gdrive:` is already configured in `rclone`
- `~/.local/bin/rclone` exists and supports `bisync`

## Commands

First-time initialization:

```bash
bash sync_data.sh init
```

Normal manual sync:

```bash
bash sync_data.sh sync
```

Rebuild the bisync baseline:

```bash
bash sync_data.sh resync
```

Check whether local and remote are in sync:

```bash
bash sync_data.sh check
```

## Notes

- `sync_data.local.env` is local-only and ignored by git.
- `sync_data.filters.md5` is generated by `rclone bisync` and ignored by git.
- If `sync_data.filters` changes, run `bash sync_data.sh resync` before the next normal `bash sync_data.sh sync`.
- Do not run sync while `rosbag record` or CSV post-processing is actively writing into `multilink_copilot/data`.
